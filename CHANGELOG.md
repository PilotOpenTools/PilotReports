# Журнал изменений - Reports

Формат: раздел `## [X.Y.Z] - дата` на каждую версию. Текст раздела становится описанием GitLab Release.

## [Не выпущено]

## [1.5.0] - 2026-11-20

- Модуль вынесен из монорепозитория PilotProAdmin в отдельный репозиторий PilotOpenTools/PilotReports. Релизы собирает GitHub Actions: сборки клиента Pilot берутся из публичного дистрибутива Pilot-BIM (`tools/get-pilot-client.ps1`), пакет Pilot.ClientSdk из релизов PilotClientSdk (`tools/get-clientsdk.ps1`).
- В поставляемом `Reports.config.json` адреса пусты (раньше там был адрес лаборатории автора). Впишите `statsUrl`, `reportsGitLabGroupUrl` и `gitLabOAuthClientId` до сборки или правьте файл рядом с dll; пока `statsUrl` пуст, статистика выключена, пока пуст `reportsGitLabGroupUrl`, отправка в GitLab недоступна.
- Источник пакетов в `nuget.config` указан примером (`gitlab.example.local`): замените на адрес своего GitLab. Сборка из чистого клона без своего GitLab описана в README, раздел 7.
- Выкладка из CI: ключи по контурам `DEPLOY_KEY_TEST`, `DEPLOY_KEY_STAGE`, `DEPLOY_KEY_PROD` вместо общего `DEPLOY_KEY` и токен задания `X-Job-Token` в каждом запросе к админке. Проверка библиотек шлёт только токен задания.
- Задание CI `test_module` запускает тесты на Windows-раннере (включается переменной `WINDOWS_RUNNER=true`), тесты входят в `Reports.sln`, тестовый проект собирает модуль в той же конфигурации, что и тесты.
- Ссылки из ответов GitLab открываются в браузере только со схемой http или https. Токен GitLab по http отправляется открытым текстом: модуль пишет предупреждение в лог.
- Чтение токена из `git credential fill`: `git.exe` ищется только в каталогах `PATH`, зависший git не блокирует поток дольше 5 с и завершается.
- Тесты: добавлены тесты атрибутов объектов, параметров отчёта, открытия ссылок и поиска git; интеграционный тест без `REPORTS_IT_URL` теперь пропускается (Skipped), а не проходит вхолостую.
- Сборки клиента Pilot (шесть dll АСКОН) убраны из репозитория. Для компиляции берутся из установленного Pilot-BIM, каталога `PILOT_CLIENT_DIR` или `lib/pilot` (`PilotClient.props`); в CI - из пакета `pilot-client` в реестре пакетов GitLab проекта (версия в `PILOT_CLIENT_VERSION`), который загружает администратор скриптом `tools/publish-pilot-client.ps1`. Версия модуля не меняется.
- Сборка решения в Debug (в том числе в Visual Studio) больше не падает на компиляции разметки WPF: тестовый проект собирал модуль второй раз параллельно в тот же каталог obj. Тесты не зависят от внутреннего устройства объектов клиента Pilot и проходят на сборках клиента разных версий.

- Адрес и ключ статистики теперь задаются в общих настройках Pilot, раздел «Модули», без пересборки модуля. Файл `Reports.config.json` действует, пока раздел пуст.

## [1.4.0] - 2026-11-02

- Исправление прода из окна публикации уходит в ветку hotfix/<дата-время> от main: прямой отправки в main больше нет.
- Адрес сервера статистики и GitLab в конфиге: адрес сервера вместо localhost - статистика и отправка отчётов работают с других машин.
- CI по шаблону веб-админки, версия только в csproj.

## [1.3.0] - 2026-10-10

- Стартовый класс `ModuleStartup` реализует `IModule` и вызывает `StartupRunner.Run(this)`: в окне «Загрузка модулей» видны статус запуска и время, ошибка инициализации - «ошибка запуска».
- Зависимость от `Pilot.ClientSdk` (NuGet-пакет, только для компиляции): на сервере должен быть модуль Pilot.ClientSdk 2.0.0 или новее.
- CI/CD по общему шаблону клиентских модулей: `dev` / тест, `release/X.Y.Z` / стейдж, `main` / прод.
